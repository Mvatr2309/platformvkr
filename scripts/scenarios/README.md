# Сценарные проверки

HTTP-сценарии против запущенного приложения: вход под тестовыми аккаунтами, запросы к страницам и API, сверка ответов. Проверяют то, что не видно в `tsc` и сборке: кто что видит и что может сделать.

## Что нужно

- Локальная база с копией прода и тестовыми аккаунтами `*@test.local`, пароль у всех `test12345`.
- Приложение запущено на `http://localhost:3000`:

```bash
docker compose up -d db
npm run build && CRON_SECRET=local-scenario-secret AUTH_TRUST_HOST=true npm start
```

`CRON_SECRET` нужен, чтобы `security-legacy.mjs` проверил рассылку с верным секретом; без него эта ветка помечается пропущенной.

На проде не запускать: сценарии меняют настройки доступа потоков и поток тестового студента, создают запросы и уведомления, а в конце всё возвращают как было.

## Запуск

```bash
node --env-file=.env scripts/scenarios/a1-cohort-platform-access.mjs
node --env-file=.env scripts/scenarios/m1-request-revision.mjs
node --env-file=.env scripts/scenarios/a2-expert-role.mjs
CRON_SECRET=local-scenario-secret node --env-file=.env scripts/scenarios/security-legacy.mjs
```

Другой адрес или пароль — через `BASE_URL` и `TEST_PASSWORD`. Код выхода ненулевой, если хоть одна проверка упала; в конце печатается список упавших.

Проверки экрана ищут текст только в разметке (`visibleHtml`): Next кладёт пропсы клиентских компонентов в скрипты страницы, и в сыром HTML текст есть, даже если на экране его нет.

## Сценарии

| Файл | Требование | Что проверяет |
|---|---|---|
| `a1-cohort-platform-access.mjs` | A1 | Доступ к «Платформе ВКР» по потокам: заглушки страниц и 403 в API для закрытого потока, независимость от трубы, закрыто по умолчанию, изменение без перелогина, уведомления и онбординг закрытого потока, другие роли не затронуты |
| `security-legacy.mjs` | Проверки субагентами, записи #48, #52, #53 | Черновики проектов не отдаются без прав, лента проекта только после входа и неоткрытая — только своим, внешний эксперт не ходит в API платформы и не получает её уведомления, база знаний ровно по флажкам, рассылка напоминаний только по секрету или админу. Рассылку вызывает на дату 100 000 дней назад — писем не бывает. Создаёт временный проект-черновик и удаляет его |
| `a2-expert-role.mjs` | A2 | Одна учётная запись с ролями научника и эксперта: 409 с ролью в «Внешних экспертах», выдача роли научнику с карточкой из профиля, запреты для студента, эксперта и админа, «Принять участие», галочка в «Создании аккаунтов» для новых и существующих научников, подсказка карточки, внешний эксперт не становится научником. Заводит временного научника и удаляет его |
| `m1-request-revision.mjs` | M1 | Возврат на доработку и повторная отправка со всеми ветками (закрытый поток, скрытый эксперт, снимок программы, чужой проект), обязательный комментарий, комментарий при одобрении студенту, отклонение (в том числе из «На доработке»), атомарность решения модератора, эксперт не видит запросы до одобрения |
