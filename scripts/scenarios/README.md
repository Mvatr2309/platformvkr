# Сценарные проверки

HTTP-сценарии против запущенного приложения: вход под тестовыми аккаунтами, запросы к страницам и API, сверка ответов. Проверяют то, что не видно в `tsc` и сборке: кто что видит и что может сделать.

## Что нужно

- Локальная база с копией прода и тестовыми аккаунтами `*@test.local`, пароль у всех `test12345`.
- Приложение запущено на `http://localhost:3000`:

```bash
docker compose up -d db
npm run build && AUTH_TRUST_HOST=true npm start
```

На проде не запускать: сценарии меняют настройки доступа потоков и поток тестового студента, создают запросы и уведомления, а в конце всё возвращают как было.

## Запуск

```bash
node --env-file=.env scripts/scenarios/a1-cohort-platform-access.mjs
node --env-file=.env scripts/scenarios/m1-request-revision.mjs
```

Другой адрес или пароль — через `BASE_URL` и `TEST_PASSWORD`. Код выхода ненулевой, если хоть одна проверка упала; в конце печатается список упавших.

## Сценарии

| Файл | Требование | Что проверяет |
|---|---|---|
| `a1-cohort-platform-access.mjs` | A1 | Доступ к «Платформе ВКР» по потокам: заглушки страниц и 403 в API для закрытого потока, независимость от трубы, закрыто по умолчанию, изменение без перелогина, уведомления и онбординг закрытого потока, другие роли не затронуты |
| `m1-request-revision.mjs` | M1 | Возврат запроса на доработку и повторная отправка, обязательный комментарий, комментарий при одобрении студенту, эксперт не видит запросы до одобрения |

## Тестовые аккаунты

| Аккаунт | Роль | Для чего |
|---|---|---|
| `test.admin@test.local` | Админ | Модерация, «Доступ по потокам», метрики |
| `test.supervisor@test.local` | Научник | Без роли эксперта |
| `test.supervisor2@test.local` | Научник | Сценарий подключения роли эксперта |
| `test.student.open@test.local` | Студент | Поток 2025, открыто всё |
| `test.student.locked@test.local` | Студент | Поток 2026, закрытый поток |
| `external.expert@test.local` | Внешний эксперт | Только труба |
